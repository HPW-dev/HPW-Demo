# Система сборки H.P.W
Замена SCons и CMake на Python. Основная причина сосздания -
фикс лимита на длину команд LD в Windows, которую SCons не вывез.

## Возможности
* инкрементальная сборка.
* многопоток.
* очистка.
* цветные логи.
* определение системы.
* автоматизация паковки ассетов.

## Как пользоваться
Просто билд игры, авто выбор потоков и закидка зависимостей по папкам:\
```py build.py --author __NICK__```

Билд в 16 потоков для кор-два-дуба без паковки ресурсов:\
```py build.py --author __NICK__ --threads 16 --cxx-opt w32-core2 --no-assets```

Чистка билда:\
```py build.py --clean```

## Структура файлов
* build.py - рулит шагами сборки, принимает аргументы запуска
* common - общая папка:
  + argparser - конвертит мои флаги во внутреннее представление.
  + hash - для хэшей файлов.
  + fs - работа с файлами.
  + ui - цветные логи.
  + host - инфа о системе, с которой билдят.
  + options - паки опций для GCC.
  + target - форматы бинарников и список файлов для сборки.
* actions - основные действия сборщика:
  + prepare-build - чекает что папки для блида готовы и лицухи с исходниками на месте.
  + clean - очистить от .o/.dll/.exe/.so файлов.
  + copy-info - копирует лицензии, инфу о сборке, флаги сборки и версии либ.
  + prepare-assets - сжимает ассеты в архив и кидает куда надо.
  + build-single - однопоточный билдер Cxx.
  + build-multi - многопоточный билдер Cxx.
  + build-multi-incremetal - многопоточный билдер Cxx с учётом пересборки изменений.
  + print-info - показывает сводку сборки.
* tests - тесты модулей сборщика:
  + test-all.py - запускает все тесты.
  + test-ui.py
  + test-io.py
  + test-clean.py
  + test-build-single.py
  + ...

## Что не умеет делать сборщик
