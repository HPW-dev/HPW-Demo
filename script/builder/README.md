# Система сборки H.P.W
Замена SCons и CMake на Python. Основная причина сосздания -
фикс лимита на длину команд LD в Windows, которую SCons не вывез.

## Возможности
* инкрементальная сборка.
* многопоток.
* очистка.
* цветные логи.
* определение системы.
* автоматизация паковки ассетов.

## Как пользоваться
Просто билд игры, авто выбор потоков и закидка зависимостей по папкам:\
```py build.py --author __NICK__```

Билд в 16 потоков для кор-два-дуба без паковки ресурсов:\
```py build.py --author __NICK__ --threads 16 --cxx-opt w32-core2 --no-assets```

Чистка билда:\
```py build.py --clean```

## Структура файлов
* __main__.py - рулит шагами сборки, принимает аргументы запуска
* common - общая папка:
  + argparser - конвертит мои флаги во внутреннее представление.
  + hasher - для хэшей файлов.
  + io - работа с системой и файлами.
  + log - цветные логи.
  + host - инфа о системе, с которой билдят.
  + options - паки опций для GCC.
* actions - основные действия сборщика:
  + prepare-build - чекает что папки для блида готовы и лицухи с исходниками
                    на месте, а так же таскает нужные либы в папку.
  + clean - очистить от .o/.dll/.exe/.so файлов.
  + prepare-assets - сжимает ассеты в архив и кидает куда надо.
  + build - разные способы компиляции .exe/.dll/.so:
    - single - однопоточный билдер Cxx.
    - multi - многопоточный билдер Cxx.
    - multi-incremetal - многопоточный билдер Cxx с учётом пересборки изменений.
  + prepare-info - показывает сводку сборки. Копирует лицензии, инфу о сборке,
                   флаги сборки и версии либ.
                   
Тесты этих модулей лежат отдельно:
  + test-log.py
  + test-io.py
  + test-clean.py
  + test-build-single.py

## Что не умеет делать сборщик
* Собирать под андроид, браузер и мак.
* Собирать через Clang и MSVC.
* Качать либы из интернета.
